# 研究生工具組(grad toolkit)

針對論文寫作生命週期的功能。執行任一功能前先讀該小節；共通原則同 SKILL.md(誠實優先、書目不靠記憶、有紅旗標紅旗)。

其中 annotate → find/counter → strength → claims 可串成「證據層建構流」：丟一篇無引用的文章，產出完整的 claim–evidence 結構。

## annotate <檔案或段落> — 標記哪句需要引用

1. 逐句分類，四種判定：
   - **需要引用**：實證宣稱(數據、比較、因果、趨勢、「研究顯示」)
   - **視慣例**：領域常識或教科書級定義(給理由，讓使用者裁量)
   - **不需外部引用**：作者自己的方法/結果/主張(但要確認行文有標明是自己的)
   - **建議改寫**：模糊量詞(「最近」「廣泛」「許多研究」)——先限定範圍再談引用
2. 已掛引用的句子標「已有引用，可跑 check 驗證」，不重複處理。
3. 輸出 `citation_needed_map.md`(或 .json)：句子|判定|理由|建議英文查詢詞。**判定含領域慣例成分，理由必寫**，最終取捨在使用者。
4. 「需要引用」項可直接餵 `find`(查詢詞已備好)。

## counter <論點> — 主動找反面證據

`find` 找支持，counter 找**不支持**——學術寫作真正需要知道的是兩邊都有什麼。

1. 查詢設計(關鍵，別只把論點翻譯成英文)：除原方向外，**必查**反向與空結果詞組——
   `no association` / `null effect` / `mixed evidence` / `no significant` / `contrary` + 搭配 `meta-analysis` / `longitudinal` / `replication`。
2. 判讀紀律與 find 相同(摘要證據、quality_warnings)，方向反轉：收「摘要明確報告無關聯/反向/結果混雜」的文獻。**零結果研究是這裡的一級素材**(平常查核最怕誤用的，在這裡正是要找的)。
3. 輸出：支持 N / 反對 N / 無顯著 N + **措辭建議**——證據混雜時，建議寫「關係仍存在不一致結果」而非單向斷言，並附兩邊代表文獻。
4. 誠實聲明必寫：出版偏誤讓反面文獻天生難搜，「找不到反面」≠「沒有反面」。

## strength <文獻+論點> — 證據強度評級

支持度(✅⚠️❌❓)回答「這篇有沒有支持這句話」；strength 回答**「即使支持，證據多強」**——兩個維度分開標。

| 評級 | 依據(必須在摘要/全文明寫) |
|---|---|
| HIGH | 統合分析、系統性回顧、大樣本 RCT |
| MEDIUM | 實驗設計(中小樣本)、縱貫追蹤、大樣本觀察研究 |
| LOW | 橫斷面、自陳問卷、單一機構小樣本、質性(僅對「因果宣稱」而言) |
| UNKNOWN | 摘要看不出設計與樣本——誠實標，不推測 |

- 評級理由必列(如「cross-sectional, N=42, self-report」)。
- **LOW ≠ 爛研究**：是「對因果宣稱的證據力低」；質性研究對機制探索可能正是對的方法。評的是證據與宣稱的匹配度，不是文獻的價值。
- 報告呈現：`✅ 支持|強度 LOW(橫斷面， n=42, 自陳)`——一眼看懂能撐多重的話。

## claims <檔案> — Claim–Evidence 總表

把 annotate + find/counter + strength 的結果彙整成一張表，每個 claim 一列：

| Claim | 支持(篇) | 反對(篇) | 最高強度 | 總評 |
|---|---|---|---|---|

總評規則：HIGH 級支持且無反對 → **Strong**；支持與反對並存 → **Mixed**(這不是壞事，是文獻回顧的好素材)；僅 LOW 支持 → **Weak**；查無 → **None**(回 annotate 的建議：改寫或標註)。

- 這張表就是文獻回顧章的骨架、`rehearse` 的題庫(Mixed 和 Weak 是口試必問區)。
- 表下必附：每筆判定的證據出處(連回各 claim 的詳細判讀)，與「本表基於檢索樣本」聲明。

## map <主題> — 領域地圖

**分流(先確認使用者要盤的是哪一層)**:本指令盤的是**文獻**——誰在發表、哪幾篇是經典、文獻怎麼分期。若使用者要的是「這個領域現在有哪些**做法**、每一種買到什麼付出什麼、哪些飽和哪些還在動」，那是**技術盤點**，本指令答不出來(它回的是文獻清單，不是做法的取捨)。環境裝有 research-gap-hunter 時交給它的 landscape；沒有就如實說明本指令只到文獻層，不要拿文獻清單硬充做法清單。同一個領域兩份都想要很合理，但兩份不要混寫在一起。

回答三個問題：奠基文獻是哪幾篇？關鍵作者是誰？近三年往哪走？

1. `search "<主題>"` + `search "<主題> survey/review"` 各一輪(limit 10)。
2. 對被引前 2 名跑 `snowball`:`references` 挖奠基、`citations` 挖最新重要後續。
3. 彙整輸出 `field_map.md`:
   - **奠基文獻**(全部候選中被引最高 5 篇，附年份與一句摘要定位)
   - **關鍵作者**(在候選中重複出現 ≥2 次的作者)
   - **近三年高影響**(year ≥ 今年-3 且被引相對高)
   - **年代分布**(候選文獻按年分桶，看領域是興起還是成熟)
4. **誠實聲明必寫**：地圖基於 20–40 篇檢索樣本，不是全域統計；關鍵作者判斷受檢索詞偏差影響。

## gap <X 與 Y 的交集> — Research gap 偵測

**分流(先確認要做的是哪一件事)**:本指令處理「X 與 Y 的交集有沒有人做」這種**已界定**的問題——使用者已經指名兩個概念，只想知道那一格是不是空的。若使用者根本還沒有題目、或需要完整的候選生成與逐一淘汰，那不是本指令的工作(見第 5 點)。

1. 交集查詢 2–3 組不同措辭(`"X Y"`、同義詞替換、上位詞放寬)。
2. 判讀：命中多且直接 → 「已有人做」附代表文獻；命中少或全是擦邊 → 「交集稀疏」。
3. 稀疏時的報告**必須包含**：最接近的文獻(各自缺哪半邊)、換詞建議清單(gap 結論最怕檢索詞不對)、以及「檢索不到 ≠ 沒人做過」的聲明——建議使用者再用中文庫與 Google Scholar 人工掃一輪才下結論。
4. 加值：對最接近的 1–2 篇跑 `snowball citations`，看引用它們的人有沒有正在補這個 gap。
5. **交棒(題目生成不在本指令範圍)**:以上是「使用者已經指名 X 與 Y」時的單一交集查證。若使用者其實還沒有 X 與 Y——他要的是題目本身，或原本的題目被判為已有人做而需要另找出路——那是**候選生成**而不是交集查證，本指令不做。環境裝有 research-gap-hunter skill 時交給它，從它的第 0 步(條件盤點)重跑；它會回頭直接呼叫 `scripts/lit_api.py` 做淘汰查證，不會重寫本 skill 的檢索與判定邏輯。沒有該 skill 時，如實告訴使用者：本指令只能查證他指名的交集，不能代他想題目——把「稀疏」講成「所以你應該做這個」是越界。

## matrix <文獻清單或主題> — 文獻矩陣

寫文獻回顧章的核心工序：把 N 篇文獻整理成可比較的表。

1. 收集對象：使用者給清單(DOI/標題)→ `batch`/`verify` 抓齊；給主題 → 先跑模式 A 收 8–15 篇；**使用者已直接提供材料(檔案/摘要)→ 跳過收集，直接填表**。
2. 每篇填欄位：**作者年份|研究問題|方法|樣本/資料|主要發現|限制|與使用者主題的關聯**。
   - 資料來源優先序：摘要 → OA 全文(方法與樣本常不在摘要，有 `openAccessPdf` 就抓，用 PyMuPDF 抽 method/results 段)→ 填不出的格標 **❓**，絕不腦補。
   - **證據層級五種**，每格必標：`[摘要]`、`[全文 p.X]`、`[書目]`(作者年份欄用)、`[綜合判斷](依據：…)`(僅「關聯」欄——該欄本質是整理者分析，前三種層級不適用)、`[❓]`。
   - **允許格內混標**：「樣本/資料」常見「評測基準有據、訓練語料查無」的混合，有據部分正常標、查無部分標 ❓；統計時「部分有據」單獨計數。
   - 「限制」欄摘要通常不寫，❓ 是預期行為——但別預設如此，有些摘要會自述限制(值得優先收錄)。
3. 輸出 markdown 表(欄多時轉置：一篇一節)；使用者要 csv 就給 csv。**強制附聲明**：書目年份可能是 arXiv 首發年而非正式刊出年，正式引用前用 `crossref-doi` 核一次。
4. **驗收(不自驗)**:subagent 可用時，派 fresh agent **分層抽查**——至少 1 格 `[全文 p.X]`(頁碼宣稱最需驗)、1 格 `[❓]`(查無宣稱也要驗)，再隨機補滿 3–5 格；不可用時明講「矩陣未經獨立抽查」。

## notes <DOI 或標題> — 閱讀筆記卡

1. `verify`/`paper` 抓書目+摘要；有 OA 全文就抓。
2. 產出 `notes/<第一作者-年份>.md`，固定模板：

```markdown
# <標題>
<作者>(<年份>)<venue>|DOI|被引 N(查核日)
## 研究問題
## 方法與樣本
## 主要發現(含具體數據)
## 限制
## 可引句(逐字+出處層級：摘要/全文 p.X)
## 與我研究的關聯(留白給使用者)
```

3. 只有摘要時，「方法與樣本」常填不滿——標 ❓ 並註明；不要用泛泛語言撐版面。

## integrity <檔案> — 引用完整性檢查

```bash
python scripts/cite_integrity.py <檔案>        # 支援 .docx/.md/.txt
```

三向核對：引了沒列、列了沒引、列表重複/跳號。確定性腳本、零 API 成本，**任何查核(check)交付前都順手跑一次**。限制：只支援數字式引用([n])；作者-年份(APA)格式如實告知不支援、需人工。

## glossary <檔案> — 術語一致性

中文論文引英文文獻的常見病：同一英文術語前後翻譯不一致。

1. 全文掃描抽「英文術語 ↔ 中文翻譯」對(含「中文(English)」與「English(中文)」兩種寫法)。
2. 報兩種病：同一英文詞對到多個中譯(hallucination：幻覺/虛構)、同一中譯對到多個英文詞。
3. 輸出 `glossary.md`(建議統一譯法欄留給使用者決定)。長文分段掃，純 LLM 作業無 API 成本。

## rehearse <檔案或章節> — 審稿人/口試預演

1. 若已跑過 `check`，以查核報告為底；沒跑過先跑(至少存在性+支持度)。
2. 對每筆引用產 1–2 個審稿人視角的提問，類型輪替：
   - 選擇性：「為何引這篇而非 <同領域更高被引的那篇>？」(用 snowball 結果找對照)
   - 理解度：「這篇的主要限制是什麼？你的研究怎麼避開？」
   - 對應性：「這篇支持你的論點到什麼程度？」(部分支持的引用最容易被追問——查核報告的 ⚠️ 就是題庫)
3. 每題附「建議答法方向」——從摘要/查核證據出發，不編造。

## watch <DOI 清單> — 新文獻哨兵

追蹤關鍵文獻的新引用者(領域動態雷達)。

1. 首次：對每個 DOI 跑 `snowball citations`，把 citing paper 清單存 `watch_state.json`。
2. 之後每次執行：重跑 → 與 state diff → 新增者中被引數或相關性突出的，列入摘要通知；更新 state。
3. 排程：Claude Code 可用排程功能(如每週一次)自動跑；**Codex 無排程**，同指令手動執行即可——文件要如實寫這個差異。
4. 誠實限制：citations 端點只回傳前 N 筆，超高被引文獻的 diff 可能漏；新文獻被引數普遍為 0，判「突出」主要靠相關性而非引用數。
